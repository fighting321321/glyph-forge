# 开发路线

> 当前路线是初始规划，不是固定承诺。GlyphForge 仍处于探索阶段，每个阶段都应先验证关键假设，再进入下一阶段。

## Phase 0：调研与问题拆解

目标：先理解字体工程问题，而不是立即实现“大而全”的生成系统。

重点任务：

- 调研 OpenType / TrueType / UFO / Glyphs 等相关格式与生态。
- 调研 FontTools、fontmake、ufoLib2 等成熟工具。
- 了解中文字体常见制作流程。
- 选择一小组代表性 Latin 与汉字作为实验集。
- 列出需要被程序表示的设计信息。
- 明确哪些问题可以规则化，哪些必须保留人工修正。

阶段产出：

- 技术调研记录；
- 最小实验字符集；
- 初始数据表示草案；
- 第一批架构决策。

## Phase 1：最小字形表示

目标：建立可以真正画出并导出少量字形的最小模型。

重点任务：

- 定义基础坐标系和字体度量。
- 实验笔画 / 路径 / 轮廓的表示方式。
- 定义少量全局风格参数。
- 创建最小 Latin 与汉字示例。
- 能够通过脚本生成可检查的轮廓结果。

阶段产出：

- 最小 glyph 数据结构；
- 可运行的生成脚本；
- 示例字形；
- 可视化或导出结果。

## Phase 2：部件复用与结构组合

目标：验证“复用”是否真的能够降低中文字体制作成本。

重点任务：

- 表示偏旁与可复用部件。
- 实验左右、上下等常见结构。
- 定义位置、缩放和留白约束。
- 观察同一部件在不同字符中的变形需求。
- 区分通用规则与字符特定修正。

阶段产出：

- 组件系统原型；
- 一组可比较的生成字符；
- 对机械拼装局限性的实验结论。

## Phase 3：风格系统

目标：把“字体风格”从单个轮廓中进一步抽象出来。

可能研究：

- 笔画粗细；
- 端点形态；
- 转角；
- 曲率；
- 重心；
- 横竖比例；
- 字面率；
- 圆角 / 锐角倾向；
- Latin 与 CJK 的跨文字系统协调。

阶段产出：

- 一组明确的 style parameters；
- 多种参数组合下的字形对比；
- 风格传播稳定性评估。

## Phase 4：字体构建与验证

目标：进入真正可使用的字体工程流程。

重点任务：

- 从源定义构建标准字体文件。
- 字符映射。
- 字体度量。
- OpenType 表。
- 自动验证。
- 可重复构建。
- 最小测试页面或测试程序。

阶段产出：

- 可安装测试字体；
- 自动构建脚本；
- 自动检查流程。

## Phase 5：扩大字符覆盖

前提：前面的表示和工作流已经证明有效。

目标：逐步增加字符覆盖，而不是盲目追求数量。

重点：

- 按常用字符频率扩展。
- 识别新的结构类型。
- 对规则覆盖不到的字符增加例外机制。
- 衡量新增字符的人工成本。

## Phase 6：高级方向

是否进入这些方向取决于前面实验结果：

- 更高级的参数化字形；
- 可变字体 Variable Fonts；
- 自动光学校正；
- 视觉相似性检查；
- AI / ML 辅助设计；
- 游戏或 Web 工具集成；
- 图形化编辑器。

其中 AI 不是默认路线。只有当传统规则化与程序化方法出现明确瓶颈，并且 AI 能解决具体问题时再引入。
